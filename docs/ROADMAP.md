# 도면3D 마스터 플랜

> 지금까지 만든 것: [CHANGELOG.md](CHANGELOG.md) · 구조 설계: [ARCHITECTURE.md](ARCHITECTURE.md) · 결정 기록: [DECISIONS.md](DECISIONS.md) · 아이디어 보관함: [IDEAS.md](IDEAS.md)

## 0. 이 문서를 읽는 법

- **트랙**: 큰 기능 묶음 (기반, 부품 설계, 도면, 메쉬·게임, 조립, 제조, 플랫폼, 연구).
- **단계**: 실제로 만드는 순서. 번호 = 추천 순서. 한 단계가 끝나면 앱이 동작하는 상태로 배포된다.
- **세부 단계 (예: 7.1)**: 단계를 나눈 작업. 각각 **완료 기준**이 있고, 그것을 자동 시험으로 확인해야 끝난 것으로 본다.
- **상세화 방식**: 가까운 단계(7~9)는 세부 단계와 완료 기준까지 자세히, 먼 단계는 무엇을 왜 하는지까지 적어 두고 **착수 직전에 같은 수준으로 다시 상세화**한다
  (기술 조사 결과와 새 아이디어가 그 사이에 바뀌기 때문). 이것을 “착수 전 상세화”라고 부른다.
- 상태: ✅ 완료 · 🔨 진행 중 · ⏭ 다음 · 📋 계획 · 🔬 연구 · ⏸ 보류
- **번호를 다시 매김 (2026-11-07)**: 사용자 요청으로 **11 도면 완성(STEP → 모든 치수·DWG)**, **12 설치형 앱**을 새로 넣고 예전 11~22단계는 13~24단계가 됐다. 10단계까지의 기록은 그대로.

## 1. 비전

**시중에 따로따로 있는 도구들을 하나로 합친 통합 3D 제작 도구.**

| 지금 사람들이 쓰는 도구 | 하는 일 | 도면3D에서 |
|---|---|---|
| SolidWorks · Fusion 360 · Onshape · FreeCAD | 치수로 정확한 부품·조립품 설계 | 부품 설계·조립 작업 공간 |
| AutoCAD · DraftSight | 2D 도면, 치수·공차 | 도면 작업 공간 (3D에서 자동 생성 + 직접 편집) |
| Blender · Maya · 3ds Max | 자유로운 메쉬 모델링, UV·재질, 애니메이션, 렌더, 게임 에셋 | 메쉬·게임 작업 공간 |
| Cura · PrusaSlicer · CAM 소프트웨어 | 3D 프린팅·가공 준비 | 제조 작업 공간 |

**핵심 차별점: 데이터가 끊기지 않는다.** 한 파일 안에서 같은 부품이 여러 작업 공간을 오간다.
치수로 설계한 부품을 고치면 → 도면, 게임용 메쉬, 프린팅 파일이 따라 바뀐다. (지금은 도구를 옮길 때마다 내보내기·가져오기로 연결이 끊긴다.)

## 2. 원칙

1. **기반 먼저.** 기능이 수십 개로 늘어도 버티는 구조(문서 모델, 명령 시스템, 작업 공간 모듈)를 기능보다 먼저 만든다.
2. **한 번에 한 단계.** 단계마다 완료 기준을 다 채워야 다음 단계로 간다. 중간에 생긴 아이디어는 보관함으로.
3. **늘 동작하는 앱.** 단계가 끝날 때마다 배포 가능한 상태. 예전 프로젝트 파일은 계속 열린다(파일 형식이 바뀌면 자동 변환).
4. **시험 없이는 완료가 아니다.** 단위 시험 + 브라우저 자동 시험 + 성능 목표(6장).
5. **큰 결정은 기록한다.** 기술 선택·방향 전환은 [DECISIONS.md](DECISIONS.md)에 이유와 함께.
6. **AI는 보류.** 꼭 필요한 곳은 다른 방법과 비교 연구(R2)한 뒤 결정한다. 지금 있는 AI 기능은 “실험 기능”.
7. **오프라인·개인정보 우선.** 기본 기능은 인터넷 없이, 사용자 파일은 사용자 컴퓨터에.
8. **새 기능만큼 다듬기.** 9단계부터 모든 단계에 **“다듬기” 세부 단계**를 둔다: 이미 만든 기능 중 느린 것·불편한 것·엉킨 코드를 고르고, 고치기 전과 후를 재서 나아진 것을 기록한다.
9. **벤치마킹.** 단계를 시작할 때 같은 문제를 푼 도구(FreeCAD, Onshape, Blender, Fusion …)의 방식을 찾아보고, 가져올 점과 버릴 점을 계획에 적는다.
10. **설치형 앱, 나중에 패드까지.** 제품은 설치하는 앱(윈도우·맥, 나중에 iPad·안드로이드)이다. 웹판은 같은 코드로 시험·미리 보기용으로 남긴다.
    새로 만드는 화면은 **터치·펜으로도 쓸 수 있게**(손가락 크기의 단추·손잡이, 마우스 오른쪽 버튼·키보드 없이도 되는 길) 만든다.

**순서를 이렇게 정한 이유**
- 7~9는 모든 트랙이 함께 쓰는 바닥이다. 여기서 문서 구조를 잘못 잡으면 나중에 전부 다시 만들어야 한다.
- **도면 완성(11)과 설치형 앱(12)을 먼저 (2026-11-07 사용자 요청)**: 다른 CAD의 STEP 파일로 치수가 다 들어간 DWG 도면을 만드는 것이 지금 바로 쓸 일이다.
  치수는 웹판에서도 바로 쓰이므로 11을 먼저, DWG 저장은 변환기를 실행해야 해서 설치형 앱(12)에서.
- 부품 설계(10, 13)를 메쉬(15~)보다 먼저: 지금 앱의 중심이 기계 부품이고, “CAD 부품 → 게임 메쉬” 연결(16)이 통합 도구의 핵심 가치라서 CAD 쪽이 먼저 단단해야 한다.
- 메쉬 편집(15)은 CAD와 독립적이라 13과 **나란히 진행할 수도 있다**(R5만 끝나면). 게임 기능을 더 빨리 원하면 15를 13 앞으로 당긴다.
- 조립품(19)은 덩치가 커서 부품 설계·게임 기초 뒤에 둔다. 기계 설계가 더 급하면 14와 15 사이로 당긴다.
- 패드 앱(23)은 12단계의 앱 틀(Tauri는 iPad·안드로이드도 같은 코드)과 원칙 10(터치·펜)을 지켜 온 화면 위에 올린다.
- **순서는 단계 경계마다 다시 정할 수 있다.** 그때 아이디어 보관함도 함께 정리한다.

## 4. 단계별 상세 계획

### 7단계: 작업 기반 ✅
> 끝남 (2026-11). 만든 것과 시험 결과는 [CHANGELOG](CHANGELOG.md#7단계에서-만든-것-작업-기반-작업이-사라지지-않게). 아래는 계획 당시 그대로.

**목표**: 작업이 절대 사라지지 않고, 여러 작업을 오가며, 인터넷 없이도 쓸 수 있다.
**왜 지금**: 기능이 커질수록 “실수로 덮어씀”의 피해가 커진다. 지금은 자동 저장이 한 칸뿐이라 새 부품·예제·가져오기를 하면 이전 작업이 덮인다(실행 취소로만 되돌릴 수 있고 새로 고침하면 사라짐).

| 세부 | 내용 | 완료 기준 |
|---|---|---|
| 7.1 프로젝트 보관함 | 브라우저 저장소(IndexedDB)에 여러 프로젝트. ‘내 프로젝트’ 창: 썸네일·이름·수정 시각, 검색, 열기·복제·이름 바꾸기·삭제. 새 부품·예제·파일 열기·가져오기는 **새 프로젝트**로 만든다. 지우면 휴지통(30일 뒤 영구 삭제). 예전 자동 저장 한 칸은 보관함으로 자동 이전 | 프로젝트 3개를 오가며 고쳐도 각자 유지, 새로 고침 뒤에도 유지, 삭제→휴지통→복원 |
| 7.2 버전 기록 | 자동 버전(고치는 동안 10분마다, 되돌리기·3D 파일 닫기처럼 큰 변화 직전), 직접 버전 저장(이름 붙이기). ‘버전 기록’ 창: 시각·이름·썸네일·바뀐 내용 요약(도형 몇 개 늘고 줄었는지), 되돌리기·새 프로젝트로 복사·삭제. 자동 버전은 프로젝트마다 최근 50개 | 되돌린 뒤 Ctrl+Z로 다시 원래 상태, 자동 버전 개수 제한 동작 |
| 7.3 자동 복구·안전장치 | 같은 프로젝트를 다른 탭에서도 열면 경고, 저장 공간 부족 알림, 예상 못 한 오류 알림(“작업은 저장돼 있어요”), **전체 백업 내보내기·가져오기**(모든 프로젝트와 3D 파일·밑그림을 한 파일로) | 두 탭 경고, 백업 → 다 지움 → 백업 가져오기로 그대로 복원 |
| 7.4 오프라인 설치 (PWA) | 앱으로 설치(바탕화면 아이콘, 창), 처음 열 때 모든 파일(3D 엔진 23MB 포함)을 저장해 두고 인터넷 없이 실행, 새 버전이 나오면 “새로 고침” 알림, 오프라인 표시 | 한 번 연 뒤 인터넷을 끊고 새로 고침해도 앱·3D 생성·도면 출력 동작 (자동 시험) |
| 7.5 실험 기능 정리 | 도면 이미지 가져오기·AI 검토·AI 설계 검토에 “실험” 표시, 설정에서 실험 기능 숨기기 | 숨기면 메뉴·버튼이 사라지고 다른 기능은 그대로 |

### 8단계: 앱 구조 — 명령 시스템, 작업 공간 모듈, 설정 ✅
> 끝남 (2026-11). 만든 것과 시험 결과는 [CHANGELOG](CHANGELOG.md#8단계에서-만든-것-앱-구조). 계획에서 바뀐 것: **inch 단위는 10단계로** 옮김(결정 12) — 아래는 계획 당시 그대로.

**목표**: 기능을 수십~수백 개 붙여도 코드와 화면이 엉키지 않는 구조. (Blender·FreeCAD·VS Code가 쓰는 방식)
**지금의 문제**: 메뉴·단축키·버튼이 `main.ts` 한 파일(7단계 뒤 약 1,800줄)에 섞여 있다. 기능 하나 추가할 때 여러 곳을 고쳐야 한다.
**7단계에서 넘어온 것**: 실험 기능 켜기·끄기와 저장 공간 정보는 지금 설정 창에 임시로 있다 → 8.6 설정 화면으로 옮긴다. ‘내 프로젝트’·‘버전 기록’ 창, 알림(notice)은 8.4에서 작업 공간과 같은 모듈 규칙을 따르게 한다.

| 세부 | 내용 | 완료 기준 |
|---|---|---|
| 8.1 명령 레지스트리 | 모든 동작을 “명령”(이름, 설명, 단축키, 실행 가능 조건, 실행)으로 등록. 메뉴·리본·단축키·명령 검색이 같은 명령을 부른다 | 기존 동작 전부가 명령으로 옮겨지고 기존 시험 통과 |
| 8.2 명령 검색 (Ctrl+K) | 이름으로 아무 기능이나 찾아 실행 (Blender F3, VS Code Ctrl+Shift+P 같은) | 모든 명령이 검색되고 실행됨 |

### 10단계: 스케치 2.0 — 구속 조건 ✅

> 끝남 (2026-11). 만든 것과 시험 결과는 [CHANGELOG](CHANGELOG.md#10단계에서-만든-것-스케치-20--구속-조건). 계획에서 바뀐 것: 길이 단위는 Onshape·Fusion 360처럼 **식 안의 맨 숫자를 쓰는 자리로 정하는 방식**으로(결정 20), three.js는 **필요할 때 내려받기**(결정 21) — 아래는 계획 당시 그대로.

**목표**: 정식 CAD처럼 “대충 그리고 조건으로 모양을 정하는” 스케치 — 지금의 세 뷰(정면 XZ · 평면 XY · 우측면 YZ 평면) 스케치에 **구속 조건과 해석기**를 넣는다.
조건을 바꾸면 모양이 따라 바뀌고, 다 정해졌는지(자유도)와 부딪치는 조건을 알려 준다.

**R4 연구 결과 (벤치마킹)**
- [FreeCAD 스케처(PlaneGCS)](https://wiki.freecad.org/Sketcher_Dialog): DogLeg·Levenberg–Marquardt·BFGS로 풀고, 행렬 계수(rank)를 QR로 구해 **중복·충돌 구속**을 진단. 중복이면 자유도를 덜 없애는 구속을 지목([PR #1429](https://github.com/FreeCAD/FreeCAD/pull/1429))
- [SolveSpace](https://gitea.suzanne.soy/suzanne.soy/solvespace/src/tag/v2.0/system.cpp): 수정 뉴턴법, 한 걸음은 **최소 노름 최소제곱**(x = Aᵀ(AAᵀ)⁻¹b — 가장 적게 움직이는 해), 끌 때는 변수에 가중치, Jacobian 계수로 **자유도 = 미지수 − 계수**
- [planegcs WebAssembly](https://github.com/Salusoft89/planegcs): FreeCAD 해석기를 웹으로 옮긴 것이 있으나 라이선스가 자료마다 다름(LGPL / MulanPSL) → **쓰지 않고 직접 만든다**(TypeScript, 우리 도형 모델에 맞춤, 크기 작음)
- 결정: SolveSpace식 최소 노름 뉴턴 + 수렴 안 되면 감쇠(LM) + Gram–Schmidt 계수 분석(나중에 넣은 구속을 중복·충돌로 지목) — [DECISIONS](DECISIONS.md) 18
- **범위 조정**: 임의 평면·부품 면 위 스케치와 따로 서는 선·원호·스플라인·참조선은 **피처 단계(지금 13단계)**로 — 스케치가 3D가 되려면 돌출·회전 피처가 필요하므로 거기서 함께(결정 19)

### 11단계: 도면 완성 — STEP에서 모든 치수, 치수 직접 놓기, AutoCAD 진짜 치수 ⏭

**목표**: 다른 CAD에서 받은 STEP(그리고 우리 부품)을 열면 **만들 수 있을 만큼의 치수가 다 들어간 도면**이 나오고, 빠진 것은 도면에서 재서 직접 놓는다.
DXF에는 AutoCAD가 **치수로 알아보는 진짜 치수**가 들어가서, AutoCAD에서 DWG로 저장해도 치수가 살아 있다. (DWG를 앱에서 바로 저장하는 것은 12단계)

**벤치마킹**
- [SOLIDWORKS 자동 치수](https://help.solidworks.com/2022/English/SolidWorks/Sldworks/t_Autodimensioning_a_Drawing.htm): 가로·세로를 따로 **기준선·연속·좌표 치수** 중에서, 원점(첫 세로선) 기준. 가져온 부품은 모델 치수가 없어 이 방식이 주된 치수 → **가져옴**
- [Onshape 도면 치수](https://www.onshape.com/en/resource-center/tech-tips/dimension-tools-onshape-drawings): 무엇을 고르냐에 따라 종류를 정함(전체 원 → 지름, 원호 → 반지름), 구멍은 치수 대신 **구멍 지시** → **가져옴** (지금 구멍 지시와 같은 방식)
- [ezdxf DIMENSION](https://ezdxf.readthedocs.io/en/stable/dxfentities/dimension.html): AutoCAD는 치수의 **그림 블록이 꼭 있어야** 연다(BricsCAD는 없으면 스스로 그림) → 그림 블록을 우리가 만들어 넣는다

| 11.1 형상 읽기 | STEP 모델의 면을 종류별로 읽어 **특징 목록**으로: 축 방향 평면(높이·단차 위치), 원통(전체 = 구멍·보스·축 지름, 일부 = 필렛 R·둥근 끝), 기울어진 평면(모따기 C·각도), 원뿔(카운터싱크·모따기 구멍), 슬롯(반원통 둘 + 평면) | 단위 시험: 예제를 STEP으로 저장했다 다시 읽어 R·C·단차·보스·슬롯이 크기·위치까지 맞음 |
| 11.2 자동 치수 2.0 | 뷰마다 바깥 윤곽과 단차를 **기준선(또는 좌표) 치수**로, 필렛 R·모따기 C 지시선, 보스·축 Ø, 슬롯 폭·길이, 구멍(지금처럼). 같은 치수는 한 뷰에만, 글자·선이 겹치지 않게 자리 잡기. **치수 빠짐 검사**: 특징마다 크기와 위치가 도면 어딘가에 있는지 확인해 빠지면 알림 | 단위 시험: 예제 부품들이 빠짐 검사 통과, 겹치는 글자 0 |
| 11.3 치수 직접 놓기·재기 | 도면 출력 화면에 **치수 도구**: 선 끝·원 중심·원호에 붙어서 두 점 → 가로·세로·평행 치수, 원 → Ø, 원호 → R, 두 선 → 각도. 놓은 치수와 자동 치수 옮기기·숨기기·지우기, 글자 덧붙이기(공차 등), 실행 취소. 도면마다 저장(.b3d). 터치로도 (원칙 10) | 브라우저 시험: 재고 놓기·옮기기·지우기·실행 취소·저장 왕복, 손가락(터치) 흉내로도 |
| 11.4 진짜 치수로 내보내기 | DXF에 **DIMENSION**(가로·세로·평행·지름·반지름·각도) + 그림 블록 + 치수 스타일, 한글 글꼴 스타일. SVG·인쇄도 같은 치수 | 시험: ezdxf로 읽어 치수 개수·값·종류 확인, 검사(audit) 오류 없음 |
| 11.5 다듬기 | ① 2D 설계에서 선택 치수와 구속 치수 글자가 겹치는 문제(아이디어 보관함) ② 큰 STEP 도면 만드는 시간 재고 줄이기 ③ 도면 출력 화면 정리 | 전·후 수치 |

## 5. 연구 트랙

연구는 단계와 나란히 진행하고, 결과는 **결정 기록**으로 남긴다. 단계가 연구 결과를 기다려야 하면 표의 “먼저 끝나야 할 것”에 적혀 있다.

### R1. 도면 인식 엔진 개혁 (이미지 → 도면) 🔬

5단계의 영상 처리 방식은 깨끗한 CAD 도면은 잘 읽지만, 손·태블릿 스케치는 모양만 대략 읽고 **치수 숫자와 뷰 이름을 읽지 못한다.** 제대로 “인식하고 사고하는” 엔진으로 다시 만든다.

1. **평가 기준 만들기**: 도면 100장 모음(CAD 출력, 스캔, 사진, 손 스케치, 태블릿 메모) + 정답(뷰, 외형, 구멍, 치수 값과 위치). 점수: 뷰 인식률, 외형 오차, 구멍 찾기 정밀도·재현율, 치수 읽기 정확도.
2. **지금 방식의 점수 재기** (기준선)
3. **단계별 개선 후보**
   - 벡터화: 선·원호를 픽셀 덩어리가 아니라 획(스트로크)으로 추출 → 손 그림에도 강하게
   - 글자 영역 분리: 치수 글자·메모·뷰 이름을 선과 분리
   - 글자 읽기(OCR): 방식은 R2와 함께 결정 (전용 OCR, 작은 학습 모델, AI)
   - 치수 연결: 읽은 숫자를 어느 선·원에 붙는 치수인지 연결(치수선·화살표·지시선 추적)
   - 추론: 치수가 그림 크기보다 우선, 3각법 관계로 뷰끼리 맞추기, 모순 찾기
   - 사람 확인 화면: 확실하지 않은 것만 빠르게 확인받기
4. 목표 점수를 넘으면 5단계 기능을 교체

### R2. 설계 도우미 방식 결정 (AI를 쓸지, 무엇으로 할지) 🔬

AI(클라우드 대형 모델)는 정확하지만 비용·인터넷·개인정보 문제가 있다. **같은 일을 다른 방법으로 할 수 있는지 비교한 뒤 결정한다.**

| 방식 | 장점 | 단점 | 어울리는 일 |
|---|---|---|---|
| 규칙·지식 기반 (표준 표, 설계 규칙, 계산) | 무료, 오프라인, 결과가 늘 같고 설명 가능 | 규칙을 사람이 다 만들어야 함 | 구멍 규격, 가장자리 거리, 공차, O-링 홈, 나사 물림 |
| 전용 OCR·영상 처리 | 오프라인, 빠름 | 손글씨·흐린 사진에 약함 | 인쇄된 도면의 치수 읽기 |
| 작은 전용 학습 모델 (브라우저에서 실행) | 오프라인, 무료, 개인정보 보호 | 학습 데이터·학습 작업 필요 | 손글씨 숫자, 기호 인식 |
| 사용자 컴퓨터의 공개 대형 모델 | 오프라인, 개인정보 보호 | 좋은 그래픽카드 필요, 설치 번거로움 | 도면 이해, 대화 |
| 클라우드 AI (지금의 실험 기능) | 가장 정확, 이해·추론 | 비용, 인터넷, 파일이 밖으로 나감 | 복잡한 검토, 대화형 설계 |
| 반자동(사람 확인 중심) | 정확도 문제를 사람이 보완 | 사람 손이 감 | 모든 경우의 마지막 확인 |

진행: ① 각 방식으로 같은 시험(R1의 도면 모음 + 설계 검토 사례)을 돌림 ② 정확도·비용·속도·오프라인·개인정보 점수표 ③ 일마다 방식을 고름(섞어 쓸 수 있음) ④ 결정 기록.
**결정 전까지**: 지금의 AI 기능은 실험 기능으로 두고 새 AI 기능은 만들지 않는다. 규칙 기반 검사는 계속 늘린다(어느 쪽으로 결정해도 쓸모 있음).

### R3. 대화로 설계하기 ⏸

“M5 볼트 4개로 모터를 고정할 브래킷” → 초안 → “두께 더 두껍게” → 수정. R2에서 방식이 정해지면 상세화. 명령 시스템(8단계)이 있어야 대화가 명령을 실행할 수 있다.

### R4. 구속 해석기·형상 커널 (10단계 전) 🔬

## 6. 공통 품질 기준 (모든 단계)

- **시험**: 새 기능마다 단위 시험 + 브라우저 자동 시험. 예제 파일 왕복(저장→열기)이 그대로인지.
- **성능 목표**: 처음 열기 3초 안(설치 후 1초), 도형 50개 부품의 3D 갱신 1초 안, 입력 반응 16ms(화면 끊김 없음).
- **호환**: 예전 파일은 늘 열린다(자동 변환), 설치형 앱(윈도우·맥, 12단계부터) + 웹판(크롬·엣지·사파리 최신 버전), 터치·펜 입력(원칙 10).
- **안전**: 작업 손실 없음(7단계 기준), 외부로 파일이 나가는 기능은 항상 사용자가 켜야 함.
- **문서**: 단계가 끝나면 CHANGELOG·README·사용법 갱신, 결정 기록.
- **다듬기**: 단계마다 이미 있는 기능을 하나 이상 더 낫게(속도·크기·편의·코드 정리), 전·후 수치를 CHANGELOG에.

## 7. 새 아이디어를 다루는 법

1. 떠오르면 [IDEAS.md](IDEAS.md)에 한 줄로 적는다 (무엇을, 왜). 그 자리에서 만들지 않는다.
2. 단계가 끝날 때마다 보관함을 정리한다: **어느 트랙에 속하는지**, **크기**, **먼저 필요한 것**을 붙이고 단계에 배치하거나 보관.
3. 큰 아이디어(새 트랙급)는 이 문서의 지도와 [ARCHITECTURE.md](ARCHITECTURE.md)가 감당하는지 확인한다. 구조가 바뀌어야 하면 결정 기록부터.
