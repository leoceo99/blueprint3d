# 구조 설계

통합 3D 제작 도구로 커지기 위한 지금의 구조와 목표 구조. 계획은 [ROADMAP.md](ROADMAP.md).

## 1. 지금 구조 (12단계까지)

```
브라우저
├─ main.ts (131줄)            모듈을 순서대로 붙이기만
├─ 작업 공간 (workspaces/*)   2D 설계 · 3D 보기 · 도면 출력 (+ 예제) — 각자 보이기/숨기기·명령, 탭·숫자 키는 자동
├─ 앱 (app/*)                 명령 시스템 · 단축키 · 메뉴 · 명령 찾기 · 설정 · 패널 배치 · 파일 · 프로젝트 · 알림
├─ 패널 (panels/*)            트리 · 변수 · 속성 · 설계 검사
├─ 화면 부품 (ui/*)           제도판(sketch + 구속 표시 sketchConstraints · 도형 유틸 sketchShapes · 색 sketchColors), 3D 보기(필요할 때 내려받기, app/lazyViewer), 대화창들
├─ 상태 (store.ts)            열린 문서(부품[]·도면[]·장면[]) + 편집 중인 부품 + 실행 취소 기록(문서 전체, 바뀐 곳만) + localStorage 즉시 저장
├─ 문서 모델 (core/document)  부품·도면 id 참조, 예전 프로젝트 변환 · 파일 형식 .b3d(core/b3d, zip)
├─ 보관 (session·library·db)  IndexedDB: 프로젝트[], 버전[], 큰 파일 — 0.8초 모아 저장, 10분마다 자동 버전, 썸네일
├─ 앱 껍데기 (pwa.ts, sw.js)  설치 정보, 오프라인 캐시(빌드 파일 전부), 새 버전 알림, 여러 탭 감지(tabs.ts) — 웹판만
├─ 설치형 앱 (src-tauri, Rust) 같은 웹 코드를 창에 띄우고, 파일 읽기·쓰기 · 연 파일 받기(한 번만 실행) · DWG 변환기 실행만 맡음
│                             화면 쪽 연결은 app/native.ts (앱이 아니면 아무것도 안 함, Tauri 코드는 앱에서만 내려받음)
├─ 순수 로직 (core/*)          3면도→3D 규칙, 검사, 변수·식(단위 포함, expr·params·units), 구속(constraints) + 해석기(solver), 도면 만들기, 이미지 인식, STL·STEP
└─ 백그라운드 스레드
   ├─ worker.ts               OpenCascade(WASM): 3D 만들기, 투영, 내보내기, STEP 읽기
   └─ visionWorker.ts         도면 이미지 인식
```

- 문서 = **부품 여러 개**(각각 정면·평면·우측면 스케치 + 변수 + (선택) 밑그림·가져온 3D 파일) + **도면 여러 장**(부품 참조 + 용지·척도·표제란) + 장면(15단계용, 비어 있음)
- 3D는 “세 뷰를 돌출해서 겹치는 부분” 또는 “회전” 규칙으로 만든다 (피처 기록 없음)
- 구속(10단계): 뷰마다 구속 목록. 편집이 끝날 때마다 store가 바뀐 값을 고정하고 해석기로 나머지를 풀며, 못 풀면 그 편집을 되돌린다(편집 종류와 상관없이 한 곳에서)
- 길이 단위(10단계): 값은 늘 mm, 부품의 `units`는 표시·입력·식의 맨 숫자에만. 화면 글자는 `core/units`의 fmtLen으로
- 도면 치수(11단계): 3D를 만들 때 워커가 형상 특징(features3d)도 함께 돌려주고, 도면은 특징 → 자동 치수(autoDims) → 도면에 저장된 고침(숨김·옮김·직접 놓은 치수, `Drawing.edits`) 순서로 치수 목록(SheetDim)을 만든다. 같은 치수 목록으로 화면·SVG·DXF(DIMENSION)를 그린다. 도면 코드는 도면 화면을 열 때 내려받음

**한계**: 부품끼리 위치 관계(조립)가 없음 → 19단계, 메쉬 객체는 자리만 → 15단계, 변수는 부품마다(문서 공용 변수는 19단계).
(8단계로 “기능이 main.ts에 몰림”, “실행 취소가 통째 복사”는 해결. 명령 시스템·작업 공간 모듈이 목표 구조의 모양대로 들어갔다.)
(7단계로 “여러 프로젝트 · 버전 · 오프라인”은 해결. 보관함은 프로젝트 JSON을 통째로 다루므로 9단계 .b3d 문서로 바뀌어도 그대로 쓸 수 있게 했다.)

## 2. 목표 구조

```
┌──────────────────────────── 작업 공간 모듈 ────────────────────────────┐
│ 부품 설계 │ 빠른 3면도 │ 도면 │ 조립 │ 메쉬 편집 │ UV·재질 │ 렌더 │ 제조 │ … │
└──────────────┬───────────────────────────────────────────────────────┘
               │ 명령만 통해서 문서를 바꾼다 (메뉴·단축키·명령 검색·플러그인·대화 모두 같은 길)
┌──────────────▼──────────────┐     ┌──────────────────────────────┐
│ 명령 시스템                  │────▶│ 실행 취소 기록 (명령 단위)       │
└──────────────┬──────────────┘     └──────────────────────────────┘
┌──────────────▼──────────────────────────────────────────────────────┐
│ 문서 모델 (.b3d)                                                      │
│  부품[] ─ 스케치[] ─ 피처 트리                                        │
│  조립품[] ─ 부품 배치 + 결합 조건                                      │
│  장면[] ─ 메쉬 객체[] (모디파이어, 재질, UV, 뼈대)                      │
│  도면[] ─ 시트[] ─ 뷰(어느 부품/조립품을) + 치수·주석                    │
│  공용: 변수, 재질 라이브러리, 단위                                      │
│  연결: “이 메쉬는 저 부품에서 변환됨” → 부품이 바뀌면 다시 변환           │
└──────────────┬──────────────────────────────────────────────────────┘
┌──────────────▼──────────────┐  ┌───────────────────┐  ┌──────────────┐
│ 계산 엔진 (워커)              │  │ 저장               │  │ 입출력          │
│  B-rep 커널 (OpenCascade)    │  │  보관함·버전 기록   │  │  STEP·STL·DXF │
│  구속 해석기 (R4)             │  │  (IndexedDB)       │  │  glTF·OBJ·3MF │
│  메쉬 커널 (R5)               │  │  .b3d 파일          │  │  SVG·PDF     │
│  인식 엔진 (R1)               │  │  클라우드(21)       │  │               │
└─────────────────────────────┘  └───────────────────┘  └──────────────┘
```

### 원칙
1. **문서는 명령으로만 바뀐다.** 그래야 실행 취소·버전 기록·플러그인·(나중의) 대화형 설계가 모두 같은 방식으로 동작한다.
2. **계산은 워커에서.** 화면 스레드는 그리기와 입력만. 무거운 계산은 결과를 캐시하고, 바뀐 부분만 다시 계산한다.
3. **형상은 두 가지 표현.** 정확한 B-rep(기계 부품)과 메쉬(게임·렌더·프린팅). B-rep → 메쉬는 언제든 가능, 메쉬 → B-rep은 제한적.
4. **작업 공간은 모듈.** 작업 공간마다 자기 화면·도구·명령을 등록한다. 새 작업 공간을 붙여도 다른 곳을 고치지 않는다.
5. **파일 형식은 버전이 있다.** 예전 파일은 변환기로 늘 열린다.

## 3. 지금 → 목표 옮기는 순서

| 단계 | 바뀌는 곳 |
|---|---|
| 7 | 저장: 보관함·버전 기록(IndexedDB), 오프라인(서비스 워커) |
| 8 | 명령 시스템, 작업 공간 모듈, main.ts 나누기, 실행 취소 2.0 |
| 9 | 문서 모델 2.0과 .b3d, 지금의 “부품 하나” 문서는 부품 1개짜리 문서로 자동 변환 |
| 11 | 도면: 가져온 모델의 형상 읽기(특징 목록) → 자동 치수, 도면마다 직접 놓은 치수 |
| 12 | 설치형 앱(Tauri): 웹 코드 그대로 + 파일 시스템·외부 변환기(DWG) 연결, 패드 대비 입력 |
| 13 | 부품 = 스케치 + 피처 트리, 지금의 3면도 방식은 “빠른 3면도” 작업 공간으로 |
| 15~ | 장면·메쉬 객체, 메쉬 커널 |
